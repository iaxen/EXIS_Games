# ZombieRush selection, grounded combat and universal EXIS UI

The map editor previously derived its floor height from the character. A saved flight altitude could leave its floor list empty, so every click failed the selection ray. The new editor first checks the floor below the character and recovers the closest visible upward surface when necessary. Floor buttons select actual neighbouring floor heights instead of assuming a six-stud interval.

A dedicated transparent map input button handles mouse and touch. Accepted points immediately display numbered dots, sequential edges and a closing edge preview. The first corner remains amber. Clicking the first marker after three corners or pressing CONNECT validates and saves the polygon for the current map. Loading/floor/input failures are shown in the editor. The independent replica camera continues to leave live combat active.

ZombieRush combat now walks using Humanoid.MoveTo. Old flight/teleport settings are migrated, flight creation is removed, and candidate positions use native standing height. The bot favors nearby live friendly turrets (with a preference for its own), holds safely inside their coverage, returns when outside, and chooses lower-risk ground routes during danger. Safety can require temporarily leaving coverage. Damage invalidates the old destination. Boss-first targeting and normal gun firing/reloading remain enabled according to their existing selections.

Movement validates map bounds, zombie exposure, body-sized collision sweeps including deployables, and floor samples for gaps, water, steep surfaces and drops. Queries and movement commands are bounded/cached. Disabling automation cancels an outstanding walk. This reduces known exposure and navigation stalls; it cannot promise zero damage or survival against every boss attack, changing map or network state.

Both ZombieRush and MrBeast now use the Fuzzotopia design: 392 × 272 initial panel, 30-pixel header, 82-pixel sidebar, matching colours and BuilderSans typography, full-row compact switches, 25-pixel accordion headers with recursive collapse, selected-tab collapse, dragging, resizing and floating minimize icon. Fuzzotopia's own implementation is unchanged. Game options and saves remain separated.

Source basis: supplied ZombieRushSurvivalCrystalMap.zip and current EXIS modules. The SkylineCity export was decoded as well; its DeployableDefinitions, ZombieTypes, MapData and ClassDefinitions match the CrystalMap export byte for byte. The selector uses each map’s loaded geometry. The supplied DeployableDefinitions exposes turret Targeting.Range (AutoTurret 42 in this export), ZombieAggroRange and ownership; ZombieTypes exposes attackRange. Configuration remains read from the game. InputObject.Position is already GUI-inset-aware according to Roblox's [InputObject documentation](https://create.roblox.com/docs/reference/engine/classes/InputObject), so map input is kept in that coordinate space instead of subtracting a guessed top-bar height.

Validation runs production helpers with simulated floor geometry, input events, marker objects, turret states, damage, routing and UI interactions. It covers both mouse and touch, map-part corners, close-on-first-corner, polygon validation, boss priority, defense planning, firing adapters, configuration isolation and the previous MrBeast tests. Full Lua parsing is included. Roblox/executor behavior and live network/physics remain untested.

In-game checks: open AREA, select a new boundary, verify each numbered dot appears, CONNECT, and reload to confirm the correct map retains it. Check FLOOR +/− on both maps. Enable combat near a turret, confirm grounded movement and boss targeting, approach zombies to check dodge/reposition behavior, then disable automation and verify walking/firing stops. Check class changes, defense placement, lobby upgrades, minimizing, resizing and both mouse/touch controls.
